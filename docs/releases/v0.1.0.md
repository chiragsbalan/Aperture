# Aperture `v0.1.0` — Phase 0 foundation

Public skeleton: anyone can open the production URL and hit a healthy app
(after a possible API cold start).

## Live URLs

| Surface | URL |
|---|---|
| Web (Vercel) | https://aperture-sepia.vercel.app |
| API (Render Free) | https://aperture-api-da3c.onrender.com |
| API via BFF | https://aperture-sepia.vercel.app/api/proxy/health/ready |

## What’s included

- Monorepo: FastAPI + Next.js + Compose local stack
- CI + branch protection quality gates
- Schema foundation (UUIDv7, mixins, Alembic baseline)
- Dark cinematic shell, design tokens, axe baseline
- Same-origin BFF proxy (`/api/proxy/...`); auth cookies reserved for P1
- Early hosting: **Vercel** FE/BFF · **Render Free** API · **Supabase Free** Postgres ([ADR-0003](../decisions/ADR-0003-hosting-and-bff.md))
- Foundation ADRs accepted: [0001](../decisions/ADR-0001-phase-authority.md)–[0006](../decisions/ADR-0006-redis-search-staging.md) (content identity, auth, Redis/search staging locked for later phases)

## Known free-tier tradeoffs

- Render Free API may sleep after ~15 minutes idle (~1 minute wake).
- Supabase Free may pause after ~1 week of low activity.
- No managed database backups on the free tier — optional manual `pg_dump`.
- Cross-cloud latency (Render ↔ Supabase) is accepted for early traffic.
